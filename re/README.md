# re_driver — восстановленный Driver PC (1999)

Одна кодовая база, две цели сборки:
- **native** — самостоятельная программа (macOS Apple Silicon, Linux, Windows x64): SDL2 + OpenGL.
  Сейчас: окно, игровой цикл, проверка данных и перенесённые модули с тестами. Игра в ней
  появится по мере переноса модулей (в Game.exe ~3270 функций без учёта CRT).
- **hook** — DINPUT.dll для оригинального Game.exe: те же перенесённые функции подменяют
  оригинальные. Так каждую функцию можно проверить в живой игре, пока native не готов.

## macOS M1 (нативно)
    brew install cmake sdl2
    ./build.sh native                       # сборка + selftest -> build-native/driver
    ./build-native/driver --data /путь/к/Data_Files     # Data_Files с вашего диска
    ./build-native/driver --selftest

## Проверка функций в оригинальной игре
    brew install mingw-w64 && ./build.sh hook   # -> build/DINPUT.dll
Положить DINPUT.dll рядом с Game.exe (MD5 8e19d76a4bd5f3838a5c5cbf1cc5cfb5). На маке запускать под
Wine/CrossOver: `WINEDLLOVERRIDES="dinput=n,b" wine Game.exe`. Лог — re_driver.log;
отключить функцию: re_driver.ini, секция [disable], `ИмяФункции=1`.

## Структура
- game/        — перенесённые модули игры (имена — по путям D:\Driver\Game\*.c). Без WinAPI.
- game/gvar.h  — GAME_VAR: в hook-сборке глобал = адрес в Game.exe, в native — обычная переменная
- platform/native/ — main (SDL2), нативные DebugMalloc/DebugFree/DebugLog
- platform/win32/  — прокси DINPUT.dll и перехват (JMP rel32), install.c — список подменённых функций
- game/unported.h — список ещё не перенесённых функций Game.exe (hook: вызов по адресу; native: заглушка platform/native/stubs.c, лог «not ported: ИМЯ (адрес)»)
- tests/selftest.c — тесты перенесённых модулей (ctest)

## Правила переноса
- в файловых/игровых структурах — только типы фиксированного размера, размер проверять _Static_assert;
- указатели не хранить в структурах, которые читаются с диска (на arm64 они 8 байт);
- (стандарт v1.42) любые указатели в таблицах/списках/записях игры, которые в оригинале 32-битные, в native хранятся как uint32_t-адреса Game.exe; перевод — только через единый реестр game/reptr.h: re_ptr(адрес) → родной указатель, re_addr(указатель) → адрес (поле записи — re_rd_ptr/re_wr_ptr). Массивы GAME_VAR с известным адресом — статические области в game/reptr.c (P95_ObjA/B/C, P62_Hs1..6, буферы строк меню…); память native без адреса Game.exe (куча, строковые литералы) получает синтетический адрес 0x80000000+ (re_ptr_register_dyn, либо автоматически при re_addr). Таблицы указателей на функции — re_fn(адрес)/re_fn_addr(fn) по таблице адрес→native-функция (k_fns в reptr.c, re_fn_register); неизвестный адрес в native → NULL, вызов пропускается. В hook-сборке всё это тождество. P95_ObjPtr/P95_ObjRef — частный случай (обёртки над re_ptr/re_addr). Глобальные скалярные указатели (P56_Sprite, P15_ListHead…) остаются родными; таблица машин шага 0x148 — см. правило v1.44;
- (v1.43) таблица строк языка 00c55820 — только P97_StrAddr (game/strtab.h, 0x15e адресов); строка — re_ptr(P97_StrAddr[i]) (P65_STR); прежние P12_00c55820/G00C55820 — макросы над ней. Таблицы .data, нужные native (титры 005527a0 и т.п.), генерируются из Game.exe скриптами tools/gen_*_data.py; блоки строк, на которые в них лежат адреса, регистрируются в k_regions game/reptr.c. Блоки, выделенные игрой (DebugMalloc, файлы), регистрируются целиком (re_ptr_register_dyn) и снимаются перед освобождением (re_ptr_unregister);
- (v1.44) таблица игроков/машин 00d077c0 (шаг 0x148, 00d07888 = поле +0xc8 записи 0) — только P99_Cars (game/cartab.h, p99_car_t с _Static_assert); любое новое имя внутри неё — макрос CARTAB_VAR(тип, имя, адрес), без отдельной native-переменной; ссылки моделей машин P28_CarClean/Dam/Low — uint32 (P79_PTR). stdcall-функции пишутся как cdecl, после добавления re_hook перезапускать tools/gen_stdcall.py (stdcall_tbl.h);
